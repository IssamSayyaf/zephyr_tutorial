## SPI Protocol Fundamentals

### What is SPI?

```
┌─────────────────────────────────────────────────────────────────┐
│                    SPI BUS OVERVIEW                              │
│                                                                  │
│   ┌──────────┐                           ┌──────────┐           │
│   │  MASTER  │                           │  SLAVE   │           │
│   │          │───── SCK (Clock) ────────▶│          │           │
│   │          │───── MOSI (Data Out) ────▶│          │           │
│   │          │◀──── MISO (Data In) ──────│          │           │
│   │          │───── CS (Chip Select) ───▶│          │           │
│   └──────────┘                           └──────────┘           │
│                                                                  │
│   SCK:  Clock signal, generated by master                       │
│   MOSI: Master Out Slave In (data from master)                  │
│   MISO: Master In Slave Out (data from slave)                   │
│   CS:   Chip Select, LOW = slave selected                       │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### SPI Modes Explained

```
┌─────────────────────────────────────────────────────────────────┐
│                      SPI MODES (CPOL/CPHA)                       │
│                                                                  │
│   CPOL = Clock Polarity (idle state)                            │
│     0 = Clock idles LOW                                          │
│     1 = Clock idles HIGH                                         │
│                                                                  │
│   CPHA = Clock Phase (when to sample)                           │
│     0 = Sample on first (leading) edge                          │
│     1 = Sample on second (trailing) edge                        │
│                                                                  │
│   MODE 0 (CPOL=0, CPHA=0) - Most common                         │
│   ────────────┐     ┌──┐  ┌──┐  ┌──┐                           │
│   SCK         └──┬──┘  └──┘  └──┘  └──                          │
│                  ↑     ↑     ↑     ↑                             │
│                Sample points (rising edge)                       │
│                                                                  │
│   MODE 1 (CPOL=0, CPHA=1)                                       │
│   ────────────┐     ┌──┐  ┌──┐  ┌──┐                           │
│   SCK         └──┬──┘  └──┘  └──┘  └──                          │
│                     ↑     ↑     ↑                                │
│                  Sample points (falling edge)                    │
│                                                                  │
│   MODE 2 (CPOL=1, CPHA=0)                                       │
│   ┬──────────┐     ┌──┐  ┌──┐  ┌──┐                            │
│   │          └──┬──┘  └──┘  └──┘  └──┐                          │
│   │             ↑     ↑     ↑        │                          │
│                Sample points (falling edge)                      │
│                                                                  │
│   MODE 3 (CPOL=1, CPHA=1)                                       │
│   ┬──────────┐     ┌──┐  ┌──┐  ┌──┐                            │
│   │          └──┬──┘  └──┘  └──┘  └──┐                          │
│   │                ↑     ↑     ↑     │                          │
│                  Sample points (rising edge)                     │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### Why Each Mode Exists

```c
/*
 * MODE SELECTION DEPENDS ON SLAVE DEVICE:
 *
 * Mode 0 (CPOL=0, CPHA=0):
 *   - Most common, default for many devices
 *   - Used by: Most sensors, many flash chips
 *
 * Mode 1 (CPOL=0, CPHA=1):
 *   - Less common
 *   - Used by: Some ADCs, specific protocols
 *
 * Mode 2 (CPOL=1, CPHA=0):
 *   - Clock idles high
 *   - Used by: Some industrial devices
 *
 * Mode 3 (CPOL=1, CPHA=1):
 *   - Second most common
 *   - Used by: Many SD cards, some sensors
 *
 * RULE: Check your slave device's datasheet!
 * Using wrong mode = garbage data or no communication
 */
```

### Full-Duplex Nature of SPI

```
┌─────────────────────────────────────────────────────────────────┐
│                    SPI IS FULL-DUPLEX                            │
│                                                                  │
│   Every transfer sends AND receives simultaneously!              │
│                                                                  │
│   Time ──────────────────────────────────────────────────▶      │
│                                                                  │
│   MOSI: [CMD][ADDR][0x00][0x00][0x00]  ← Master sends           │
│   MISO: [??] [??] [D0]  [D1]  [D2]     ← Slave sends            │
│                                                                  │
│   Even during "read", master must clock data out (usually 0x00) │
│   Even during "write", slave clocks data back (usually ignored) │
│                                                                  │
│   Example: Read 3 bytes from address 0x10                       │
│   Master sends: [0x03] [0x10] [0x00] [0x00] [0x00]              │
│                  ↑       ↑      ↑      ↑      ↑                  │
│                  Read    Addr   Dummy  Dummy  Dummy              │
│                  cmd                                             │
│   Slave sends:  [----] [----] [DATA0][DATA1][DATA2]             │
│                  ↑       ↑      ↑                                │
│                  Ignore  Ignore Actual data                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## Header File Analysis

### SPI Configuration Structure

```c
/**
 * SPI Device Configuration
 *
 * WHY SEPARATE PER DEVICE: Each slave may need different settings.
 * Flash might be Mode 0, 10 MHz.
 * Display might be Mode 3, 1 MHz.
 *
 * Store settings per-device, apply when selecting that device.
 */
struct spi_advanced_device_config {
    /**
     * SPI Mode (0-3)
     *
     * HOW USED: Configures CPOL and CPHA bits in hardware.
     * MUST match slave device requirements from datasheet.
     */
    uint8_t mode;

    /**
     * Clock Frequency
     *
     * WHY VARIABLE: Different devices have different max speeds.
     * - Fast flash: 50+ MHz
     * - Slow sensor: 1-5 MHz
     * - Display: 10-40 MHz
     *
     * NOTE: Actual frequency may differ due to clock divider
     * limitations. Will be <= requested frequency.
     */
    uint32_t frequency;

    /**
     * Bit Order
     *
     * MSB_FIRST: Most significant bit transmitted first (most common)
     *   0x85 = [1][0][0][0][0][1][0][1] sent in this order
     *
     * LSB_FIRST: Least significant bit first (rare)
     *   0x85 = [1][0][1][0][0][0][0][1] sent in this order
     */
    bool lsb_first;

    /**
     * Word Size
     *
     * WHY CONFIGURABLE: Some devices use non-8-bit transfers.
     * - 8-bit: Most common, byte-oriented
     * - 16-bit: Some ADCs, DACs
     * - 9-bit: Some displays (command/data bit)
     */
    uint8_t word_size;

    /**
     * Chip Select GPIO
     *
     * WHY STORE: Each device has its own CS pin.
     * Driver manages CS: LOW before transfer, HIGH after.
     *
     * gpio_dt_spec contains:
     * - port: GPIO controller device
     * - pin: Pin number
     * - dt_flags: Active level, etc.
     */
    struct gpio_dt_spec cs_gpio;

    /**
     * CS Timing
     *
     * WHY NEEDED: Some devices need setup/hold time around CS.
     *
     * cs_delay_us: Wait after CS LOW before first clock
     * cs_hold_us: Wait after last clock before CS HIGH
     *
     * Timeline:
     * CS:  ─────┐           ┌─────
     *           └───────────┘
     *      ◄──►             ◄──►
     *      delay            hold
     *           ◄──────────►
     *            Transfer
     */
    uint16_t cs_delay_us;
    uint16_t cs_hold_us;
};
```

### Transfer Structure

```c
/**
 * Transfer Descriptor
 *
 * WHY A STRUCT: Complex transfers need multiple parameters.
 * Easier to pass one struct than many arguments.
 */
struct spi_advanced_transfer {
    /**
     * TX Buffer
     *
     * Data to send to slave.
     * NULL if only receiving (will send zeros).
     */
    const uint8_t *tx_buf;

    /**
     * RX Buffer
     *
     * Where to store received data.
     * NULL if only sending (received data discarded).
     */
    uint8_t *rx_buf;

    /**
     * Transfer Length
     *
     * Number of bytes (or words, depending on word_size).
     * MUST NOT exceed buffer sizes!
     */
    size_t len;

    /**
     * Transfer Flags
     *
     * SPI_ADV_XFER_NO_CS_RELEASE: Keep CS LOW after transfer
     *   Used for multi-part transfers:
     *   1. Send command (no release)
     *   2. Send address (no release)
     *   3. Receive data (with release)
     */
    uint8_t flags;
};
```

### Chip Select Management

```c
/**
 * Assert Chip Select
 *
 * WHY A FUNCTION: CS management has timing requirements.
 * Centralizing ensures consistent behavior.
 *
 * @param dev    SPI advanced device
 * @param dev_id Which slave to select
 */
static int cs_assert(const struct device *dev, uint8_t dev_id)
{
    struct spi_advanced_data *data = dev->data;
    struct spi_slave_data *slave = &data->devices[dev_id];

    /**
     * Step 1: Check if already selected
     *
     * Avoid unnecessary CS transitions.
     * Some devices are sensitive to extra CS toggles.
     */
    if (data->current_device == dev_id) {
        return 0;  /* Already selected */
    }

    /**
     * Step 2: Deselect current device (if any)
     *
     * Only one CS active at a time!
     */
    if (data->current_device >= 0) {
        struct spi_slave_data *current = &data->devices[data->current_device];
        gpio_pin_set_dt(&current->config.cs_gpio, 0);  /* HIGH = deselected */
    }

    /**
     * Step 3: Select new device
     *
     * CS is active LOW (most common).
     * gpio_pin_set_dt() handles active level from DT.
     */
    int ret = gpio_pin_set_dt(&slave->config.cs_gpio, 1);  /* LOW = selected */
    if (ret < 0) {
        LOG_ERR("Failed to assert CS: %d", ret);
        return ret;
    }

    data->current_device = dev_id;

    /**
     * Step 4: CS setup delay
     *
     * Some devices need time after CS before first clock.
     * Datasheet specifies this (often 10-100 ns).
     */
    if (slave->config.cs_delay_us > 0) {
        k_busy_wait(slave->config.cs_delay_us);
    }

    return 0;
}

/**
 * De-assert Chip Select
 */
static int cs_deassert(const struct device *dev, uint8_t dev_id)
{
    struct spi_advanced_data *data = dev->data;
    struct spi_slave_data *slave = &data->devices[dev_id];

    /**
     * CS hold delay
     *
     * Some devices need clock to settle before CS rises.
     */
    if (slave->config.cs_hold_us > 0) {
        k_busy_wait(slave->config.cs_hold_us);
    }

    /* Deselect */
    gpio_pin_set_dt(&slave->config.cs_gpio, 0);
    data->current_device = -1;

    return 0;
}
```

### Mode Switching

```c
/**
 * Apply Device Configuration
 *
 * WHY SEPARATE: Called before each transfer to ensure
 * correct settings for the target device.
 *
 * Builds Zephyr spi_config from our settings.
 */
static int apply_device_config(const struct device *dev, uint8_t dev_id)
{
    const struct spi_advanced_hw_config *hw_cfg = dev->config;
    struct spi_advanced_data *data = dev->data;
    struct spi_slave_data *slave = &data->devices[dev_id];

    /**
     * Build Zephyr SPI config structure
     *
     * This is what Zephyr's SPI driver expects.
     */
    struct spi_config *cfg = &slave->spi_cfg;

    /**
     * Frequency
     *
     * Zephyr will use nearest available frequency <= requested.
     * Actual frequency depends on SPI peripheral clock dividers.
     */
    cfg->frequency = slave->config.frequency;

    /**
     * Operation flags
     *
     * SPI_OP_MODE_MASTER: We are the master (generate clock)
     * SPI_WORD_SET(n): Word size in bits
     * SPI_MODE_CPOL: Set for modes 2 and 3
     * SPI_MODE_CPHA: Set for modes 1 and 3
     * SPI_TRANSFER_LSB: Set for LSB-first transfers
     */
    cfg->operation = SPI_OP_MODE_MASTER | SPI_WORD_SET(slave->config.word_size);

    /* Apply mode (CPOL/CPHA) */
    switch (slave->config.mode) {
        case 0:
            /* CPOL=0, CPHA=0 - no flags */
            break;
        case 1:
            cfg->operation |= SPI_MODE_CPHA;
            break;
        case 2:
            cfg->operation |= SPI_MODE_CPOL;
            break;
        case 3:
            cfg->operation |= SPI_MODE_CPOL | SPI_MODE_CPHA;
            break;
    }

    /* LSB first if configured */
    if (slave->config.lsb_first) {
        cfg->operation |= SPI_TRANSFER_LSB;
    }

    /**
     * Chip Select
     *
     * We manage CS manually for better control.
     * Setting cs = NULL tells Zephyr we handle it.
     */
    cfg->cs = NULL;  /* We manage CS ourselves */

    LOG_DBG("Config dev %d: mode=%d, freq=%u, word=%d",
            dev_id, slave->config.mode, cfg->frequency, slave->config.word_size);

    return 0;
}
```

### Core Transfer Implementation

```c
/**
 * Transceive Implementation
 *
 * This is where the actual SPI transfer happens.
 */
int spi_advanced_transceive(const struct device *dev,
                            uint8_t dev_id,
                            const uint8_t *tx_buf,
                            uint8_t *rx_buf,
                            size_t len)
{
    const struct spi_advanced_hw_config *hw_cfg = dev->config;
    struct spi_advanced_data *data = dev->data;
    struct spi_slave_data *slave;
    int ret;

    /**
     * Step 1: Validate device ID
     */
    if (dev_id >= CONFIG_SPI_ADVANCED_MAX_DEVICES) {
        LOG_ERR("Invalid device ID: %d", dev_id);
        return -EINVAL;
    }

    slave = &data->devices[dev_id];

    if (!slave->configured) {
        LOG_ERR("Device %d not configured", dev_id);
        return -ENODEV;
    }

    /**
     * Step 2: Acquire lock
     *
     * SPI is a shared bus. Only one transfer at a time!
     */
    ret = k_mutex_lock(&data->lock, K_MSEC(1000));
    if (ret != 0) {
        LOG_ERR("Failed to acquire SPI lock: %d", ret);
        return -EBUSY;
    }

    /**
     * Step 3: Apply device settings
     *
     * Ensures correct mode/frequency for this device.
     */
    apply_device_config(dev, dev_id);

    /**
     * Step 4: Build buffer sets
     *
     * Zephyr SPI uses spi_buf and spi_buf_set for scatter-gather.
     * We use simple single-buffer transfers here.
     *
     * WHY SCATTER-GATHER EXISTS:
     * Efficient for: [header][data][checksum] in separate buffers
     * Without copying into one contiguous buffer.
     */
    struct spi_buf tx_spi_buf = {
        .buf = (void *)tx_buf,  /* Cast away const - Zephyr won't modify */
        .len = len,
    };
    struct spi_buf_set tx_set = {
        .buffers = tx_buf ? &tx_spi_buf : NULL,
        .count = tx_buf ? 1 : 0,
    };

    struct spi_buf rx_spi_buf = {
        .buf = rx_buf,
        .len = len,
    };
    struct spi_buf_set rx_set = {
        .buffers = rx_buf ? &rx_spi_buf : NULL,
        .count = rx_buf ? 1 : 0,
    };

    /**
     * Step 5: Assert CS
     */
    ret = cs_assert(dev, dev_id);
    if (ret < 0) {
        k_mutex_unlock(&data->lock);
        return ret;
    }

    /**
     * Step 6: Perform transfer
     *
     * spi_transceive() is Zephyr's SPI transfer function.
     * It handles TX and RX simultaneously (full duplex).
     */
    ret = spi_transceive(hw_cfg->spi, &slave->spi_cfg, &tx_set, &rx_set);

    if (ret < 0) {
        LOG_ERR("SPI transfer failed: %d", ret);
        slave->error_count++;
    } else {
        slave->transfer_count++;
        slave->bytes_transferred += len;
        data->total_transfers++;
    }

    /**
     * Step 7: De-assert CS
     */
    cs_deassert(dev, dev_id);

    /**
     * Step 8: Release lock
     */
    k_mutex_unlock(&data->lock);

    return ret;
}
```

### Write-then-Read Implementation

```c
/**
 * Write-then-Read
 *
 * Very common operation: send command, receive response.
 * CS stays asserted across both phases.
 */
int spi_advanced_write_read(const struct device *dev,
                            uint8_t dev_id,
                            const uint8_t *tx_buf,
                            size_t tx_len,
                            uint8_t *rx_buf,
                            size_t rx_len)
{
    const struct spi_advanced_hw_config *hw_cfg = dev->config;
    struct spi_advanced_data *data = dev->data;
    struct spi_slave_data *slave;
    int ret;

    /* Validation */
    if (dev_id >= CONFIG_SPI_ADVANCED_MAX_DEVICES) {
        return -EINVAL;
    }
    slave = &data->devices[dev_id];
    if (!slave->configured) {
        return -ENODEV;
    }

    /* Lock */
    ret = k_mutex_lock(&data->lock, K_MSEC(1000));
    if (ret != 0) {
        return -EBUSY;
    }

    apply_device_config(dev, dev_id);

    /**
     * Build buffer sets for two-phase transfer
     *
     * Phase 1: TX only (send command/address)
     * Phase 2: RX only (receive data)
     *
     * IMPORTANT: Uses scatter-gather for both phases in one transfer!
     * More efficient than two separate transfers.
     */
    struct spi_buf tx_bufs[2] = {
        { .buf = (void *)tx_buf, .len = tx_len },  /* Phase 1: send */
        { .buf = NULL, .len = rx_len },             /* Phase 2: dummy TX */
    };
    struct spi_buf_set tx_set = { .buffers = tx_bufs, .count = 2 };

    struct spi_buf rx_bufs[2] = {
        { .buf = NULL, .len = tx_len },             /* Phase 1: ignore RX */
        { .buf = rx_buf, .len = rx_len },           /* Phase 2: receive */
    };
    struct spi_buf_set rx_set = { .buffers = rx_bufs, .count = 2 };

    /**
     * Execute as single transfer
     *
     * CS asserted for entire transfer (both phases).
     * More efficient than separate transfers.
     */
    cs_assert(dev, dev_id);

    ret = spi_transceive(hw_cfg->spi, &slave->spi_cfg, &tx_set, &rx_set);

    cs_deassert(dev, dev_id);

    /* Update stats */
    if (ret < 0) {
        slave->error_count++;
    } else {
        slave->transfer_count++;
        slave->bytes_transferred += tx_len + rx_len;
    }

    k_mutex_unlock(&data->lock);

    return ret;
}
```

### Register Access Helpers

```c
/**
 * Read Single Register
 *
 * Common SPI sensor protocol:
 * TX: [0x80 | reg_addr]    (0x80 = read flag)
 * RX: [dummy] [data]
 */
int spi_advanced_read_reg(const struct device *dev,
                          uint8_t dev_id,
                          uint8_t reg,
                          uint8_t *value)
{
    /**
     * Build read command
     *
     * Convention: Bit 7 = 1 for read, 0 for write
     * (Some devices use opposite - check datasheet!)
     */
    uint8_t cmd = reg | 0x80;  /* Set read bit */

    return spi_advanced_write_read(dev, dev_id, &cmd, 1, value, 1);
}

/**
 * Write Single Register
 *
 * TX: [reg_addr] [value]
 * RX: (ignored)
 */
int spi_advanced_write_reg(const struct device *dev,
                           uint8_t dev_id,
                           uint8_t reg,
                           uint8_t value)
{
    /**
     * Build write command
     *
     * Bit 7 = 0 for write (clear if was set)
     */
    uint8_t buf[2] = { reg & 0x7F, value };

    return spi_advanced_transceive(dev, dev_id, buf, NULL, 2);
}

/**
 * Burst Read (Multiple Registers)
 *
 * Efficient for reading consecutive registers.
 * Many devices auto-increment address.
 */
int spi_advanced_burst_read(const struct device *dev,
                            uint8_t dev_id,
                            uint8_t start_reg,
                            uint8_t *buf,
                            size_t len)
{
    /**
     * Read with auto-increment
     *
     * Some devices use bit 6 to enable auto-increment.
     * Check your device's datasheet!
     */
    uint8_t cmd = start_reg | 0x80 | 0x40;  /* Read + multi-byte */

    return spi_advanced_write_read(dev, dev_id, &cmd, 1, buf, len);
}
```

## DMA and Async Operations

### Why Use DMA

```
┌─────────────────────────────────────────────────────────────────┐
│              CPU vs DMA FOR SPI TRANSFERS                        │
│                                                                  │
│   WITHOUT DMA (CPU handles each byte):                          │
│                                                                  │
│   CPU:  [load][store][wait][load][store][wait][load][store]...  │
│   SPI:  [───byte 1───][───byte 2───][───byte 3───]              │
│                                                                  │
│   CPU is 100% busy during transfer!                             │
│                                                                  │
│   ────────────────────────────────────────────────              │
│                                                                  │
│   WITH DMA (CPU just starts and waits):                         │
│                                                                  │
│   CPU:  [setup DMA][    free to do other work    ][ISR]         │
│   DMA:  [───────── handles all bytes ──────────────]            │
│   SPI:  [───byte 1───][───byte 2───][───byte 3───]              │
│                                                                  │
│   CPU is free during transfer!                                  │
│                                                                  │
│   Best for: Large transfers (>32 bytes typically)               │
│   Overhead: DMA setup takes time                                │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### Async Transfer Implementation

```c
/**
 * Async Transceive
 *
 * Non-blocking transfer using DMA.
 * Returns immediately, callback when done.
 */
int spi_advanced_transceive_async(const struct device *dev,
                                  uint8_t dev_id,
                                  const uint8_t *tx_buf,
                                  uint8_t *rx_buf,
                                  size_t len,
                                  spi_advanced_callback_t callback,
                                  void *user_data)
{
    const struct spi_advanced_hw_config *hw_cfg = dev->config;
    struct spi_advanced_data *data = dev->data;
    struct spi_slave_data *slave;
    int ret;

    /* Validation */
    if (dev_id >= CONFIG_SPI_ADVANCED_MAX_DEVICES) {
        return -EINVAL;
    }
    slave = &data->devices[dev_id];

    /* Try to acquire lock without blocking */
    ret = k_mutex_lock(&data->lock, K_NO_WAIT);
    if (ret != 0) {
        return -EBUSY;  /* Another transfer in progress */
    }

    apply_device_config(dev, dev_id);

    /* Build buffer sets */
    struct spi_buf tx_spi_buf = { .buf = (void *)tx_buf, .len = len };
    struct spi_buf_set tx_set = {
        .buffers = tx_buf ? &tx_spi_buf : NULL,
        .count = tx_buf ? 1 : 0,
    };

    struct spi_buf rx_spi_buf = { .buf = rx_buf, .len = len };
    struct spi_buf_set rx_set = {
        .buffers = rx_buf ? &rx_spi_buf : NULL,
        .count = rx_buf ? 1 : 0,
    };

    cs_assert(dev, dev_id);

    /**
     * Store callback for async completion handler
     */
    data->async_callback = callback;
    data->async_user_data = user_data;
    data->async_dev_id = dev_id;

    /**
     * Start async transfer
     *
     * spi_transceive_async() returns immediately.
     * Callback will be called when DMA completes.
     */
    ret = spi_transceive_async(hw_cfg->spi, &slave->spi_cfg,
                               &tx_set, &rx_set,
                               async_completion_handler);

    if (ret < 0) {
        /* Failed to start - clean up */
        cs_deassert(dev, dev_id);
        k_mutex_unlock(&data->lock);
        return ret;
    }

    /* Transfer started - lock remains held until completion */
    return 0;
}

/**
 * Async Completion Handler
 *
 * Called by Zephyr when DMA transfer completes.
 * Runs in ISR context!
 */
static void async_completion_handler(const struct device *spi_dev,
                                     int result,
                                     void *user_data)
{
    const struct device *dev = user_data;
    struct spi_advanced_data *data = dev->data;

    /* De-assert CS */
    cs_deassert(dev, data->async_dev_id);

    /* Release lock */
    k_mutex_unlock(&data->lock);

    /* Call user callback (in ISR context!) */
    if (data->async_callback) {
        data->async_callback(dev, result, data->async_user_data);
    }
}
```

## Multi-Device Management

### Adding a Device

```c
/**
 * Add/Configure a Slave Device
 *
 * Called once per slave device during application setup.
 *
 * Example:
 *   struct spi_advanced_device_config flash_cfg = {
 *       .mode = 0,
 *       .frequency = 10000000,
 *       .cs_gpio = GPIO_DT_SPEC_GET(flash_node, cs_gpios),
 *   };
 *   spi_advanced_add_device(spi_dev, 0, &flash_cfg);
 */
int spi_advanced_add_device(const struct device *dev,
                            uint8_t dev_id,
                            const struct spi_advanced_device_config *config)
{
    struct spi_advanced_data *data = dev->data;
    struct spi_slave_data *slave;
    int ret;

    /* Validate */
    if (dev_id >= CONFIG_SPI_ADVANCED_MAX_DEVICES) {
        LOG_ERR("Device ID %d exceeds max %d", dev_id, CONFIG_SPI_ADVANCED_MAX_DEVICES);
        return -EINVAL;
    }

    if (config == NULL) {
        return -EINVAL;
    }

    slave = &data->devices[dev_id];

    /**
     * Configure CS GPIO
     *
     * Each device needs its own chip select.
     */
    if (config->cs_gpio.port != NULL) {
        if (!gpio_is_ready_dt(&config->cs_gpio)) {
            LOG_ERR("CS GPIO not ready for device %d", dev_id);
            return -ENODEV;
        }

        /* Configure as output, initially high (deselected) */
        ret = gpio_pin_configure_dt(&config->cs_gpio, GPIO_OUTPUT_INACTIVE);
        if (ret < 0) {
            LOG_ERR("Failed to configure CS GPIO: %d", ret);
            return ret;
        }
    }

    /**
     * Store configuration
     */
    memcpy(&slave->config, config, sizeof(*config));

    /* Set defaults if not specified */
    if (slave->config.word_size == 0) {
        slave->config.word_size = 8;  /* Default to 8-bit */
    }
    if (slave->config.frequency == 0) {
        slave->config.frequency = 1000000;  /* Default to 1 MHz */
    }

    /* Reset statistics */
    slave->transfer_count = 0;
    slave->bytes_transferred = 0;
    slave->error_count = 0;

    slave->configured = true;

    LOG_INF("Device %d configured: mode=%d, freq=%u",
            dev_id, config->mode, config->frequency);

    return 0;
}
```

### Removing a Device

```c
/**
 * Remove a Slave Device
 *
 * Deconfigures device, releases resources.
 */
int spi_advanced_remove_device(const struct device *dev, uint8_t dev_id)
{
    struct spi_advanced_data *data = dev->data;
    struct spi_slave_data *slave;

    if (dev_id >= CONFIG_SPI_ADVANCED_MAX_DEVICES) {
        return -EINVAL;
    }

    slave = &data->devices[dev_id];

    if (!slave->configured) {
        return -ENODEV;  /* Nothing to remove */
    }

    /* Ensure not currently selected */
    if (data->current_device == dev_id) {
        cs_deassert(dev, dev_id);
    }

    /* Mark as unconfigured */
    slave->configured = false;

    LOG_INF("Device %d removed (transfers: %u, bytes: %llu, errors: %u)",
            dev_id, slave->transfer_count, slave->bytes_transferred, slave->error_count);

    return 0;
}
```

### Runtime Mode Switching

```c
/**
 * Change Device Mode
 *
 * Change SPI mode for a device (e.g., some devices use
 * different modes for different operations).
 */
int spi_advanced_set_mode(const struct device *dev,
                          uint8_t dev_id,
                          uint8_t mode)
{
    struct spi_advanced_data *data = dev->data;
    struct spi_slave_data *slave;

    if (dev_id >= CONFIG_SPI_ADVANCED_MAX_DEVICES || mode > 3) {
        return -EINVAL;
    }

    slave = &data->devices[dev_id];
    if (!slave->configured) {
        return -ENODEV;

    slave->config.mode = mode;
    LOG_DBG("Device %d mode changed to %d", dev_id, mode);

    return 0;
}

 * Change Device Frequency

        return -EINVAL;

    slave = &data->devices[dev_id];
    if (!slave->configured) {
        return -ENODEV;
    }

    slave->config.frequency = frequency;
    LOG_DBG("Device %d frequency changed to %u Hz", dev_id, frequency);

    return 0;
```

## Summary

The SPI Advanced driver demonstrates:

1. **Protocol understanding**: CPOL/CPHA modes, full-duplex nature
2. **Multi-device support**: Per-device configuration and CS management
3. **Flexible transfers**: Polling and DMA modes
4. **Clean API**: Helpers for common patterns (reg read/write, burst)
5. **Runtime reconfiguration**: Mode and frequency changes
6. **Thread safety**: Mutex protection for shared bus
7. **Statistics**: Per-device and global transfer tracking

### Key Takeaways

| Concept | Why It Matters |
|---------|----------------|
| SPI Modes | Must match slave device requirements |
| CS Management | Manual control for precise timing |
| Scatter-Gather | Efficient multi-buffer transfers |
| DMA | CPU-free transfers for large data |
| Per-Device Config | Different slaves need different settings |
| Locking | Shared bus requires mutual exclusion |
